# MyaK Biplane

Прототип 2D-догфайта: **биплан против птеродактиля**. Матч с ботом считается целиком в браузере,
а сетевой матч идёт напрямую между игроками через WebRTC DataChannel: хозяин комнаты запускает
симуляцию, гость отправляет ввод. Сервер только выдаёт коды комнат и помогает установить связь.
Клиент — Blazor WASM + HTML5 Canvas.

## Что уже работает

- Детерминированная симуляция `MyaKBiplane.Core`: движение, гравитация, стрельба, урон,
  кулдауны, возрождение, счёт до 10 уничтожений.
- Два класса: биплан (инерция, повороты, ускорение, магазин на 5 патронов) и птеродактиль
  (прямое управление, рывок, заряжаемое копьё).
- Башня-маяк в центре карты: аппараты появляются по разные её стороны, а лётчик может
  катапультироваться, раскрыть парашют и добежать до башни за новым аппаратом.
- Анимация появления: биплан плавно выезжает от своего края, отрывается от земли и
  набирает высоту по единой кривой, птеродактиль влетает со своей стороны.
  Управление и защита включаются после анимации.
- Физика лётчика: катапульта вверх, свободное падение, ручной парашют на `Пробел`,
  безопасная скорость приземления и планирование. Купол можно сбить снарядом — тогда
  парашют не раскроется до возрождения.
- Локальный матч с ботом: шаг симуляции 60 Гц в браузере, без сервера и без интернета.
- P2P-матч: авторитетный хост в браузере, снимки ~30 Гц по DataChannel, ввод гостя ~30 Гц.
- Сетевая игра по коду комнаты: хозяин создаёт комнату, гость присоединяется и выбирает
  свой аппарат. Классы могут совпадать.
- Пауза по `Esc` для обоих игроков, легенда управления на паузе и реванш с подтверждением.
  Бот принимает реванш сам.
- Отдельный экран «Помощь» в меню вместо постоянной панели подсказок в бою.
- Blazor WASM клиент с Canvas: меню, HUD, частицы, экраны ожидания/паузы/победы.
- Светлая и тёмная темы интерфейса с переключателем в главном меню и сохранением выбора.
- Telegram Mini App: запуск в горизонтальной ориентации, fullscreen, синхронизация темы и
  безопасных зон, сенсорные стики и кнопки, back-кнопка и тактильная отдача; компактный масштаб
  для телефонов.
- Docker-оркестрация для release и локального debug.
- Точечные тесты ядра.

## Структура решения

| Проект | Назначение |
| --- | --- |
| `MyaKBiplane.Core` | Детерминированная симуляция матча, баланс, бот. Без зависимостей от UI и сети. |
| `MyaKBiplane.Shared` | Сетевые контракты: `GameSnapshot`, `RoomInfo`, `InputState`, версия протокола. |
| `MyaKBiplane.Game` | `SnapshotFactory`, локальная `GameSession` и `HostGameSession` для P2P-хоста. |
| `MyaKBiplane.Server` | ASP.NET Core + SignalR: реестр комнат и релей SDP/ICE, Serilog. |
| `MyaKBiplane.Client` | Blazor WASM + Canvas. Вся отрисовка в `wwwroot/js/game.js`. |
| `MyaKBiplane.Tests` | xUnit-тесты математики, физики, боя, новых механик и детерминизма. |

Проекты лежат в корне решения, без папки `src/`.

## Требования

- .NET SDK **10.0.403** или новее в ветке 10.0 (зафиксировано в `global.json`).
- Docker Desktop — для запуска через compose.
- Внешняя сеть `shared-net` и существующий PostgreSQL — только для debug-compose.
  На текущем срезе база не используется, но подключение уже предусмотрено в окружении.

## Локальный запуск без Docker

Сервер нужен только для сетевой игры (выдача кодов и сигналинг). Матч с ботом работает
без сервера; для P2P-матча сервер нужен лишь в момент создания комнаты.

Терминал 1 — сервер:

```powershell
dotnet run --project MyaKBiplane.Server
```

Сервер поднимется на `http://localhost:5179` (см. `Properties/launchSettings.json`).

Терминал 2 — клиент:

```powershell
dotnet run --project MyaKBiplane.Client
```

Клиент откроется на `http://localhost:5049`. Сервер для разработки не нужен.

Для проверки онлайна откройте два окна браузера на `http://localhost:5049`: в первом создайте
комнату и скопируйте код приглашения, во втором вставьте его и отправьте обратно код ответа.

### Игра между двумя машинами

Сервер сигналинга не нужен — достаточно, чтобы оба игрока открыли один и тот же адрес
GitHub Pages (или один и тот же локальный адрес в одной сети) и обменялись кодами.

## Сценарии меню

- **Игра с ботом** → выбор аппарата → матч против бота на аппарате противоположного класса.
- **Игра по сети** → создать комнату → выбрать аппарат и правила → код приглашения сопернику.
- **Игра по сети** → присоединиться → вставить код приглашения, выбрать аппарат, вернуть код ответа.
- **Помощь** → легенда управления и правил. Та же легенда показывается на паузе в бою.
- **Настройки** → чекбокс dev-информации: блок с режимом, правилами и пингом во время боя.

## Управление

### Биплан

- `W` / `S` — тяга вперёд / назад
- `A` / `D` — поворот
- `ЛКМ` или `F` — огонь
- `R` — ручная перезарядка магазина
- `Пробел` — ускорение (действует 5 с, затем кулдаун; после кулдауна снова доступно)
- `E` — покинуть аппарат
- `Esc` — пауза и меню матча

### Птеродактиль

- `WASD` — движение
- `Мышь` — прицел
- `ЛКМ` — удержание заряжает копьё, отпускание — бросок
- `Пробел` — рывок
- `E` — покинуть аппарат
- `Esc` — пауза и меню матча

### Лётчик

- `E` — катапультироваться: лётчика выбрасывает вверх над аппаратом
- `Пробел` — раскрыть или сложить парашют
- В свободном падении и на парашюте — горизонтальное управление (`A` / `D`)
- Планирование и купол гасят падение до безопасной скорости; слишком быстрый удар о землю
  убивает лётчика и приносит очко сопернику
- На земле — бег к башне-маяку
- `E` рядом со своим бесхозным аппаратом — забраться обратно

## Правила матча

- Матч идёт до 10 уничтожений (хозяин сетевой комнаты может задать другое значение).
  После уничтожения аппарат возрождается через 2,5 секунды.
- Появление занимает 2,4 секунды: биплан плавно выезжает от своего края, отрывается
  от земли и набирает высоту по единой кривой, птеродактиль влетает со своей стороны.
  Аппарат в это время неуязвим и неуправляем.
- После анимации управления включается стандартная защита на 3 секунды: атаковать нельзя,
  урон не проходит. Движение, ускорение и перезарядка доступны.
- Нос аппарата после появления смотрит в сторону верхнего угла соперника.
- Касание земли уничтожает незащищённый аппарат. Во время защиты аппарат лишь прижимается
  к земле.
- Разбившийся о землю аппарат с лётчиком внутри засчитывается сопернику как уничтожение.
- Башня-маяк стоит в центре карты. Точки появления — слева и справа от неё.
- При катапультировании аппарат остаётся в мире бесхозным, продолжает падать и может разбиться.
- Свободный лётчик — полноценная цель: снаряды и бот поражают его, а сбитый лётчик приносит
  стрелку очко. Попадание в купол уничтожает парашют: лётчик падает без него до возрождения.
- Добравшийся до башни лётчик получает новый аппарат с полным здоровьем и стартовой защитой.
  Жизни за это не списываются.
- У биплана 5 патронов в магазине и ручная перезарядка на 5 секунд (в 2,5 раза длиннее полной
  зарядки копья). Во время перезарядки стрельба запрещена, над аппаратом виден прогресс.
- Бот на биплане перезаряжается при пустом магазине, а также может перезарядиться заранее
  в затишье.
- Снаряды биплана — маленькие «горошины». Радиус лётчика равен 1,7 радиуса пули.

### Свои правила комнаты

Хозяин сетевой комнаты может включить «Свои настройки» на стартовом экране и изменить:

- количество уничтожений до победы (от 1 до 50, по умолчанию 10);
- можно ли обоим игрокам выбрать одинаковый аппарат (по умолчанию можно);
- разрешено ли катапультирование (по умолчанию разрешено).

Соперник видит список всех отличий от стандартных правил ещё до установки прямого
соединения, а во время боя отличия остаются в верхней панели. Если одинаковые аппараты
запрещены и гость выбрал класс хозяина, ему автоматически выдаётся другой класс —
это тоже сообщается отдельным уведомлением.

Пока соперник не подключился, хозяин может запустить локальную тренировку с ботом
кнопкой «Тренировка с ботом». Как только второй игрок входит в комнату, тренировка
останавливается и начинается сетевой матч с теми же правилами.

## Сеть и архитектура

- Матч с ботом: `LocalMatchClient` + `GameSession`, всё считается в браузере офлайн.
- Сетевой матч: `P2pMatchClient` + `js/webrtc.js` без сервера сигналинга. Хост создаёт
  код `MYAK1:…` с SDP-предложением, гость вставляет его и возвращает код ответа;
  в коде есть версия клиента, правила комнаты и ICE-кандидаты.
- Хост запускает `HostGameSession` (шаг 60 Гц) и шлёт снимки ~30 Гц по DataChannel;
  гость шлёт `InputState` ~30 Гц. Пауза и реванш тоже идут по DataChannel.
- Настройки комнаты (`RoomSettings`) хост передаёт кодом, правила симуляции (`MatchRules`)
  применяются в `HostGameSession`. Сервер в матче не участвует.
- STUN — публичные серверы Google. TURN пока не подключён: на симметричном NAT/CGNAT
  прямая связь может не установиться (подробности в [`docs/telegram.md`](docs/telegram.md)).
- Хост должен держать вкладку активной: при сворачивании браузер замедляет таймеры.

## Публикация в GitHub Pages

На GitHub Pages выкладывается только статический клиент `MyaKBiplane.Client`.
Сервер **не нужен**: матч с ботом считается локально, а сетевой матч использует
P2P с ручным обменом кодами. Документы по Fly.io остаются в репозитории как опция
на будущее, но для игры их выполнять не обязательно.

Пошаговая инструкция: [`docs/deployment.md`](docs/deployment.md). Коротко:

1. **Settings → Pages → Source = GitHub Actions**.
2. Запустите workflow **Deploy client to GitHub Pages** (или просто смержите в `master`).
3. Откройте https://ivanmyak.github.io/MyaK-Biplane/ и проверьте версию внизу меню.

Как играть по сети:

1. Хост выбирает аппарат и правила, нажимает «Создать комнату», копирует код приглашения
   и отправляет его сопернику (например, в Telegram).
2. Гость вставляет код, выбирает аппарат, получает код ответа и отправляет его хосту.
3. Хост вставляет код ответа и нажимает «Подключить соперника» — начинается матч.

Если версии клиента у игроков разные, обмен кодов завершится ошибкой с подсказкой.

### Версия проекта

Версия показывается в правом нижнем углу меню (и на экране помощи) в формате
`0.<минор>.<патч>[-dev]`:

- **минор** — количество слияний в master (`git rev-list --merges --count`). Увеличивается
  только при слиянии в главную ветвь;
- **патч** — при слиянии обнуляется и становится равным числу коммитов в слитой ветке
  (`HEAD^1..HEAD^2`). Если правки шли сразу в master — это все коммиты после последнего
  слияния (`<последний merge>..HEAD`), то есть версия растёт на каждый коммит;
- **`-dev`** — добавляется, когда сборка запущена не из master (патч в этом случае считается
  как `origin/master..HEAD`).

Примеры: `0.4.6` (правки в master), `0.5.2` (пятое слияние, в ветке 2 коммита),
`0.4.1-dev` (ветка с одним коммитом от master).

Чтобы получить `-dev`-сборку, запустите **Deploy client to GitHub Pages** вручную через
**Run workflow** и выберите нужную ветку.

Сервер отдаёт **ту же версию** в `GET /` — при деплое её записывает `scripts/deploy-fly.ps1`
в секрет `App__Version`. Поэтому деплоить сервер нужно этим скриптом, а не просто `fly deploy`:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy-fly.ps1
```

Значение вычисляется при деплое в workflow и записывается в `publish/wwwroot/appsettings.json`
(ключ `App:Version`). Локально по умолчанию отображается `0.0.0`; чтобы получить то же значение,
запустите:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/update-version.ps1
```

Через BotFather нужно создать бота, Mini App (`/newapp`) и кнопку меню (`/setmenubutton`) с URL

## Docker

### Release

```powershell
Copy-Item .env.example .env
# заполните .env при необходимости
docker compose up -d --build
```

- клиент: `http://localhost:8081`
- сервер: `http://localhost:8080`
- health-check: `http://localhost:8080/health`

Nginx проксирует `/hubs/` на `server:8080`, включая WebSocket-апгрейд.

### Debug

```powershell
Copy-Item debug.env.example debug.env
# укажите параметры существующего PostgreSQL из shared-net
docker compose --env-file debug.env -f docker-compose.debug.yml up -d --build
```

- клиент: `http://localhost:5081`
- сервер: `http://localhost:5080`
- логи сервера: `MyaKBiplane.Server/Data/Logs/<год>/`

Debug-compose **не создаёт** новый PostgreSQL. Он подключается к внешней сети `shared-net`
и использует параметры подключения из `debug.env`.

## Секреты и конфигурация

- `.env` — release-окружение, в git не попадает.
- `debug.env` — локальное окружение, в git не попадает.
- `.env.example` и `debug.env.example` — шаблоны, которые коммитятся.
- Runtime-логи и локальные данные (`Data/`) игнорируются git.

## Логирование

Serilog настраивается через `LoggingProviders` и `LogFiles` в `appsettings*.json` по схеме
проекта SchoolShedule:

- `Console` — шаблон `[HH:mm:ss LVL] Message`;
- `File` — текстовый лог;
- `Monitoring` — JSON-лог.

Путь и срок хранения задаются в `LogFiles:Root` и `LogFiles:RetentionDays`.
