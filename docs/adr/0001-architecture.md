# ADR 0001. Архитектура первого играбельного среза

- **Статус:** принято; сетевой матч пересмотрен в [ADR 0002](0002-p2p-host.md)
- **Дата:** 2026-11-16
- **Контекст:** концепт `GDD_BT_Biplanes.md`, первый прототип «биплан против птеродактиля».

## Контекст

Нужен короткий путь до играбельного результата: ПК-браузер сейчас, мобильный клиент позже.
При этом хочется сохранить возможность сетевой игры вдвоём (ПК + телефон) без переписывания
симуляции. Полноценные микросервисы для матча 1v1 избыточны: это добавит инфраструктуру,
но не ускорит проверку геймплея.

## Решение

1. **Модульный монолит на сервере.** Один ASP.NET Core процесс. Внутри — модули,
   которые при необходимости можно выделить позже. SignalR используется как транспорт
   для авторитетных матчей, но не определяет структуру домена.
2. **`MyaKBiplane.Core` — детерминированная симуляция.** Не зависит от рендера, сети и платформы.
   `GameWorld` выполняет шаг на сервере; клиент только отправляет ввод и рисует снимки.
   В том же шаге живут анимация появления, физика свободного лётчика, ручной парашют,
   безопасное приземление и начисление очков за сбитых лётчиков и разбитые аппараты.
3. **`MyaKBiplane.Game` — снимки и локальная сессия.** `SnapshotFactory` формирует сетевой
   контракт, `GameSession` с фиксированным шагом 1/60 c остаётся для тестов и отладки.
   Модуль не зависит от Blazor.
4. **`MyaKBiplane.Client` — Blazor WASM + HTML5 Canvas.** Рендер вынесен в `wwwroot/js/game.js`
   за неформальный интерфейс `start/stop` + `[JSInvokable] Tick`. Позже тот же экран
   переиспользуется в MAUI Blazor Hybrid; при нехватке FPS рендер меняется на SkiaSharp.
5. **`MyaKBiplane.Shared` — метаданные и контракты.** Версия протокола, общие DTO.
6. **`MyaKBiplane.Server` — авторитетный хост.** Комнаты, серверный шаг 60 Гц, рассылка
   снимков ~30 Гц, пауза и реванш. Serilog по схеме SchoolShedule, health-check, SignalR-хаб.
7. **Docker Desktop.** `docker-compose.yml` — release, `docker-compose.debug.yml` — локальный
   запуск. Debug не создаёт новый PostgreSQL, а подключается к существующему контейнеру
   во внешней сети `shared-net`.

## Последствия

- Быстрый старт: матч с ботом и сетевой матч по коду комнаты работают через сервер; база не нужна.
- Симуляция тестируется отдельно от UI: математика, физика, урон, кулдауны, бот, детерминизм.
- Сервер авторитетен: клиент не может изменить правила игры, только отправить ввод.
- Пауза и реванш — состояния комнаты, а не клиентские флаги.
- Легенда управления — один Blazor-компонент: меню открывает её отдельным экраном,
  пауза показывает сжатую версию. Постоянной панели подсказок в бою нет.
- Ограничение: пока нет интерполяции и реконнекта. Это осознанный следующий шаг.
- Android-клиент отложен: сначала проверяем геймплей в Web, затем упаковываем тот же UI в MAUI.
